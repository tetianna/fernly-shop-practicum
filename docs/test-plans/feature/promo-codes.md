# Test plan: feature/promo-codes

Customers can apply a promo code in the cart for a plant discount or free shipping. The change adds `POST` / `DELETE /api/cart/promo`, cart and order fields `discount` and `promoCode`, `PromoCodeInput` via the cart-summary slot, and discount lines on `OrderSummary` (cart, checkout, order detail). Seed codes: `LEAFY10` (10% off plants), `FREESHIP` (free shipping), `SPRING5` (expired 30 Apr 2026).

Oracle: `docs/features/promo-codes.md`; money/shipping in `docs/PRODUCT.md` (shipping $6.95; free from $50.00 subtotal; prices two decimals). Diff: `origin/main...HEAD`.

## Notes / ask before coding tests

| Topic | Why |
| --- | --- |
| Exact expired-code copy | Doc requires a message that the code **has expired**; OpenAPI only names rule `promo_invalid`. Confirm expected `detail` string if not fixed in app yet — tests keep the doc oracle. |
| Percent base in implementation | Feature doc says plants-only; treat PC-01 as the money oracle (report mismatch in FINDINGS, do not weaken). |
| `PromoCodeInput` label markup | Doc requires a visible label for the code field; copy today is “Have a promo code?” — PC-09 accessibility case should assert an accessible name, not a specific CSS class. |
